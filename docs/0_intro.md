# ВСТУП

## Актуальність теми

Повоєнне відновлення інфраструктури та житлового фонду України формує попит на системи, що забезпечують перевірювану звітність про хід робіт, використання матеріальних ресурсів і фактичну присутність персоналу на об'єкті. Учасники будівельного процесу (замовник, прораб, бригади, постачальники) взаємодіють через непов'язані канали, що унеможливлює єдине джерело істини щодо стану об'єкта та ускладнює аудит донорського фінансування.

З інженерного погляду задача потребує розв'язання низки проблем розподілених систем: забезпечення консистентності розподілених бізнес-транзакцій (погодження заявки, замовлення, повернення при зміні ціни), ідемпотентної обробки подій (запобігання подвійному нарахуванню робочого часу), відмовостійкості щодо зовнішніх залежностей (LLM API), масштабованості при піковому навантаженні (ранкова реєстрація присутності, безперервний потік геокоординат) та безпеки геолокаційних персональних даних. Їх розв'язання потребує застосування патернів Saga, CQRS, Transactional Outbox, Circuit Breaker, а також засобів контейнерної оркестрації, автоматизованого забезпечення якості та спостережуваності.

## Об'єкт дослідження

Процес управління виконанням будівельного проєкту в умовах розподіленої взаємодії учасників, що охоплює облік робочого часу та присутності персоналу, рух матеріальних ресурсів і контроль якості виконаних робіт.

## Предмет дослідження

Архітектурні патерни, методи та технології проєктування розподіленої подієво-орієнтованої платформи: мікросервісна архітектура, оркестрована Saga, CQRS, Transactional Outbox з ідемпотентними споживачами, Apache Kafka, Resilience4j, геопросторова верифікація засобами PostGIS, автентифікація на основі JWT з рольовим розмежуванням доступу (RBAC), контейнеризація та оркестрація (Docker, Kubernetes), CI/CD (GitHub Actions) і спостережуваність (Prometheus, Grafana, OpenTelemetry).

## Мета роботи

Проєктування та розробка розподіленої програмної платформи (PWA) для управління будівельним проєктом шляхом застосування подієво-орієнтованої мікросервісної архітектури, патернів розподіленої консистентності та відмовостійкості з метою підвищення консистентності даних, відмовостійкості та перевірюваності облікових процесів (робочий час, матеріали, хід робіт) порівняно з розрізненими каналами комунікації.

## Завдання проєкту

1. Проаналізувати предметну область та наявні програмні рішення для управління будівництвом (за ДСТУ 3008:2015), сформувати функціональні та нефункційні вимоги, включно з цільовими показниками якості (SLO).
2. Обґрунтувати вибір архітектурного стилю та технологічного стеку з документуванням рішень у форматі ADR (Kafka vs RabbitMQ, оркестрація vs хореографія Saga).
3. Спроєктувати архітектуру системи засобами C4 Model та UML, модель даних PostgreSQL/PostGIS і специфікації API (OpenAPI).
4. Розробити алгоритми критичних вузлів: скінченний автомат життєвого циклу заявки (Saga з компенсуючими транзакціями), геоверифікацію check-in з інваріантом єдиної активної сесії, ідемпотентну обробку подій (Outbox, DLQ), детекцію аномалій присутності та захищену інтеграцію з LLM API (Circuit Breaker, Retry, Bulkhead).
5. Спроєктувати інтерфейс PWA та схему розгортання (Docker, Kubernetes, Helm), налаштувати CI/CD-конвеєр і засоби спостережуваності.
6. Виконати інструментальний аудит якості та безпеки: модульне, інтеграційне та контрактне тестування, навантажувальне тестування (k6), статичний аналіз (SonarQube), сканування вразливостей (Trivy).
7. Провести апробацію результатів та підготувати науково-практичну публікацію за темою дослідження.
