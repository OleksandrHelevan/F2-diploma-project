## 1. Вступ

### 1.1. Призначення документа

Документ фіксує контракт вимог до системи Bricklayers і є джерелом для проєктування архітектури (C4 Model, ADR), розроблення тестів та інструментального аудиту якості. Кожна вимога має унікальний ідентифікатор, атомарна та верифікована методом, наведеним у розділі 5.

### 1.2. Конвенції

- **«повинна»** — обов'язкова вимога, невиконання якої означає невідповідність системи контракту.
- **Пріоритет** за MoSCoW: **M** (Must), **S** (Should), **C** (Could).
- **Методи верифікації** за ISO/IEC/IEEE 29148: **T** — тест, **A** — аналіз, **I** — інспекція, **D** — демонстрація.
- Формат ідентифікаторів: `SRS-FUN-NN` (функціональні), `SRS-NFR-<КАТЕГОРІЯ>-NN` (нефункціональні), `SRS-CON-NN` (обмеження).

## 2. System Context (Контекст системи)

### 2.1. Межі системи (Scope)

Bricklayers автоматизує три облікові контури будівельного об'єкта: присутність і робочий час персоналу з геопросторовою верифікацією, життєвий цикл заявок на матеріали, хід робіт і дефекти. Система складається з PWA-клієнта, API Gateway, Identity Provider, семи доменних сервісів, брокера подій Apache Kafka та сховищ даних і розгортається в одному кластері Kubernetes.

**Входить у межі:** керування акаунтами й ролями; об'єкти та геозони; QR-сесії та check-in/check-out; потік геокоординат і детекція аномалій; заявки на матеріали (Saga); завдання; записи прогресу; звіти про дефекти з консультативною LLM-оцінкою; push-сповіщення.

**Не входить у межі:** нарахування заробітної плати та бухгалтерський облік; складський облік постачальника; BIM-моделювання; платіжні операції; нативні мобільні застосунки.

## 7. Glossary (Глосарій)

| Термін | Визначення |
| --- | --- |
| JWT (JSON Web Token) | Компактний токен (RFC 7519) з підписаними claims, що передає ідентичність і ролі користувача між Identity Provider, API Gateway та сервісами без звернення до сховища сесій. |
| Геозона (Geofence) | Полігон у системі координат WGS 84, що описує периметр будівельного об'єкта; належність точки перевіряється функцією PostGIS `ST_Covers`. |
| Saga | Патерн керування розподіленою бізнес-транзакцією як послідовністю локальних транзакцій сервісів, у якій відмова кроку компенсується зворотними (компенсуючими) транзакціями. |
| Transactional Outbox | Патерн, за яким доменна подія записується в таблицю outbox у тій самій транзакції, що й зміна стану, а окремий процес публікує її в брокер; усуває проблему подвійного запису. |
| Ідемпотентність | Властивість операції, за якої повторне виконання з тим самим ключем (`Idempotency-Key`, `eventId`) не змінює результат після першого виконання. |
| Circuit Breaker | Патерн відмовостійкості, що після перевищення порогу помилок тимчасово припиняє виклики зовнішньої залежності та повертає резервну відповідь. |
| Eventual Consistency | Модель узгодженості, за якої репліки та проєкції даних у різних сервісах досягають однакового стану через обмежений час після завершення запису. |

**Скорочення:** PWA — Progressive Web Application; RBAC — Role-Based Access Control; DLQ — Dead Letter Queue; HPA — Horizontal Pod Autoscaler; SLO/SLI — Service Level Objective/Indicator; RPO/RTO — Recovery Point/Time Objective; DPIA — Data Protection Impact Assessment; IDOR — Insecure Direct Object Reference; PKCE — Proof Key for Code Exchange.
